# Build and asset warning review

Scope: the pinned StandardMale, whole-body, right-leg external-hemorrhage experiment, not every API or scenario in the upstream SDK.

- The final native `init`, `control`, `bleed`, `repeat`, and `restore` logs contain no `[WARN]`, `[ERROR]`, or `[FATAL]` messages. All required observation channels were finite; action/event continuity and complete active-checkpoint continuation passed.
- The asset-generator `[ERROR] verification_dir set to invalid directory ...` is a configuration diagnostic for the deliberately absent **verification baseline directory**. `DataSetReader.main` uses `cfg.getDataDirectory()/Data.xlsx`; it does not use the verification directory to generate patient/substance/environment/config assets. Generated assets round-trip successfully in the same upstream utility. No validation baseline was downloaded or represented as locally validated.
- CMake's `Protobuf` versus `protobuf` package-name author warning concerns FindPackage result-variable naming. Imported targets resolved, linked, and performed real state serialization/load. No dependency version was substituted to hide this warning.
- Dependency deprecation warnings, unused-variable warnings and signed-comparison warnings were observed during the historical native build; they are not runtime validity diagnostics.
- The `coverageModifier = coverageModifier = ...` warning at `CardiovascularModel.cpp:3050` is from GCC `-Wsequence-point`. The actual target is compiled as C++20 (see compiler/build manifest). GCC documents that this warning still diagnoses assignment forms whose ordering became defined in C++17, to flag portability to earlier language modes. The right-associative duplicate assignment is redundant, not an unsequenced increment. No upstream source was changed. Reference: https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html (`-Wsequence-point`, retrieved during review).
- Protobuf's potential null-`this` warning traces to `map.cc:274`, which passes a null message prototype while computing **key** layout. The dereference is only in the `kMessage` case at lines 253–256. Protobuf map keys are scalar/string, not messages. This is not an observed null dereference in the run; actual state save/load completed.
- The returning-reference-to-temporary warnings in `eLungCompartment_Name` are genuine upstream API defects, not declared fixed. Source search found only one caller: respiratory-mechanics-modifier string rendering (`SERespiratoryMechanicsModifiers.cpp:387`). This exporter does not call it or apply respiratory-mechanics modifiers. This is a limitation on extending the harness, not a demonstrated fault in the bounded cardiovascular experiment.
- Missing-switch cases in the same lung-name helper and in validation-target deserialization, and misleading indentation in mechanical-ventilator action validity checks, concern APIs/actions not exercised here. No ventilator, lung-modifier or validation-target action is present in the full checkpoint or exported action lists.

This is a bounded relevance review, not a claim that the complete Pulse source is warning-free or bug-free. Any extension into the affected APIs requires renewed review. Compiler warnings have not been globally suppressed and the source archive audit still reports zero modifications.
